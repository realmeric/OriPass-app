# Orion and a native messaging host, October 2026

Orion 1.1.3 (`com.kagi.kagimacOS`, team `TFVG979488`), macOS 27.0.1. Run on 2026-10-30 by a session, with no account, no vault and no page. A throwaway extension with `nativeMessaging` in its permissions was put in a throwaway home with three host manifests beside it, and its background page called each host once. Each host was the same script, which wrote what it was given to a log and answered with a size.

## a. Does Orion start a host

It does, as a child of the browser (the host's parent pid was Orion's), and reads the manifest from `~/Library/Application Support/Orion/NativeMessagingHosts/`, which is where Bitwarden's desktop app has put its own. `runtime.sendNativeMessage` under manifest version 2, with a persistent background page, worked at the first try. A background page called the three hosts within 0.3 s of each other, about a second after launch.

Each `sendNativeMessage` starts a new process, which reads one message, answers, and is left to see its standard input close. Four calls, four starts. `connectNative` was not run.

## b. Who it says is calling

`argv[1]` is the extension's origin, `chrome-extension://<id>/`, where `<id>` was the name of its folder under `Defaults/Extensions`. That is what Chrome passes too. What Orion gives an extension installed from disk was not seen.

## c. Whether `allowed_origins` is held to

It is not. A host whose manifest named another extension's origin was started and answered, and so was one whose list was empty. Any extension in Orion with `nativeMessaging` can start any host in that folder. The list is written anyway, for the day it is read; what a host may trust is `argv[1]`.

## d. How much fits

60,010 bytes went from the extension to the host in one message and came out whole, against a report on Orion's forum, from 2024, of a limit at 16,380. An answer that long was not tried; the answers here were under a hundred bytes.

## e. What is not known

Whether Orion runs a Safari web extension's `.appex` from Tools › Extensions › Install from Disk the way its help page says. The string `.appex/Contents/Resources` is in its binary, and that is all. Whether `browser.runtime.sendNativeMessage` from such an extension goes through the same folder. Neither can be run without clicking in his Orion.

## What not to do again

The throwaway home was `CFFIXED_USER_HOME`. That moved Orion's files and caches into the temp directory and did not move its preferences, which still went through `cfprefsd` to his. In the three seconds it ran, the second Orion wrote six keys of `com.kagi.kagimacOS` on the real Mac: `IsBrokenStartup` (left true, since it was killed), `PreCompiledContentRuleListVersion`, `ContentBlockerLastUpdated`, `ContentBlockingListStates`, `LastCrashCheckDate` and `ToolbarConfigurationForCompactTabs`. A copy of the file had been taken first, and those six were put back through `CFPreferencesSetAppValue` within two minutes and read back equal. The one key that differed from the copy afterwards was `lastChangeToken`, which his running Orion had moved itself.

A run like this one needs a second macOS user, or a copy of the app under another bundle id, or a person's hands.
