# `bw login` without an account, October 2026

`bitwarden-cli` 2026.9.1 from Homebrew, macOS 27.0.1. Run on 2026-10-08 by `scripts/spike-login.py`, which starts an HTTPS server on 127.0.0.1 with a certificate made for the run, points the real `bw` at it through a temporary `BITWARDENCLI_APPDATA_DIR`, and refuses every login. Nothing left the Mac and no account was involved. The CLI's sentences are measured. The server's bodies are written from what the CLI's parsing expects, so the two sentences that are the server's own ("Two-step token is invalid. Try again." and "invalid new device otp") are this script's and may not be Bitwarden's.

## Told not to ask (`BW_NOINTERACTION=true`), with `--response`

Each line is the `message` of `{"success":false,"message":…}` on standard output, exit 1.

| Case | Message |
| --- | --- |
| No password in the named variable | Master password is required. |
| Email without `@` | Email address is invalid. |
| Wrong password | Invalid master password. Confirm your email is correct and your account was created on 127.0.0.1:50929. |
| Server set with `http://` | Error: Insecure URL not allowed. All URLs must use HTTPS. |
| Second step, one method | Code is required. |
| Second step, one method, email | Code is required. (after `POST /api/two-factor/send-email-login`) |
| Second step, two methods, none named | Login failed. No provider selected. |
| Second step, two methods, `--method 1` | Code is required. (after the email is sent) |
| Second step, only a passkey | No providers available for this client. |
| `--method 42` | Invalid two-step login method. |
| New device | Code is required. |
| `--apikey`, no `BW_CLIENTID` | client_id is required. |
| `--apikey`, server answers `invalid_client` | client_id or client_secret is incorrect. Try again. |
| `--apikey`, id starting `organization.` | Invalid API Key; Organization API Key currently not supported |
| Nothing listening | FetchError: request to https://127.0.0.1:51422/identity/accounts/prelogin/password failed, reason: connect ECONNREFUSED 127.0.0.1:51422 |

Without `--response` the same sentence goes to standard error and standard output is empty.

`bw config server <address> --response` answers "Saved setting `config`." for an `http` address as well. `https://bitwarden.com` sets `serverUrl` back to null.

## Free to ask, standard input a pipe and no terminal

The question is on standard error. With `000000` and a newline written to standard input, the CLI sent a second token request carrying `twoFactorToken` and `twoFactorProvider`, or `newDeviceOtp`, and printed the server's refusal. It writes the question again after every character it reads, so standard error ends with the question and the whole code.

With two methods and none named it draws its list ("Authenticator App", "Email", a rule, "Cancel") and waits for arrow keys. With standard input closed it stays at any of the three questions until killed: sixty seconds here, then the script's own timeout.
